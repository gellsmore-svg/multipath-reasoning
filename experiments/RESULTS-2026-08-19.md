# First recorded comparison — 2026-08-19

Seven records, four oracle tasks, one model. **No significance is claimed and none
can be.** This is the first data in this directory; before it, every claim in the
repository rested on design argument alone.

## Headline

On four real debugging tasks with an objective oracle, **a single tool-using
trajectory matched ground truth on all four**, blind-graded. On the one task where a
population was also run, it matched too — at **4.9× the tokens and 5× the
invocations** for the same graded outcome.

For this task family, the population bought no measurable accuracy.

## Tasks

Each task is a real bug-fix commit from a production repository in the same estate.
The snapshot is `git archive` of the fix commit's **parent**, so the fix is
unreachable: no `.git`, verified no answer text in the tree, and no contaminating
installed dependency. The symptom given to the model is the reporter's half of the
commit message; the cause is withheld and used only for grading.

| Task | Fix commit | Symptom given |
|------|-----------|----------------|
| `hoglah-segv` | `bda0802` | intermittent exit 139 mid-suite, no traceback |
| `mahalath-witness-race` | `90a2ea3` | trace events silently dropped under concurrency |
| `milcah-queue-path` | `4f36420` | specialist calls block to a 240s timeout |
| `milcah-submitter-attr` | `356f8ce` | every call `blocked`, zero model calls, tests pass |

All four were selected because the *original engineer's* first hypothesis was wrong —
the `hoglah-segv` commit message records that the crash was "first assumed" to be at
interpreter shutdown.

**That selection criterion did not transfer.** What was hard for a human under time
pressure was not hard here. Every task was solved by one careful pass, and in most
cases the model went further than the original fix: four independent paths built
standalone reproducers and *measured* the crash rate (2/20, 3/10, 31/60, 34/40;
0/20–0/60 with the lock taken), against the commit's own "2 in 8 before, 0 in 14
after".

Grading was performed by a separate agent given only the ground truth and the
candidate text, with condition labels stripped and candidate order shuffled
(`blind_to_condition: true`). Three pre-registered key elements per task; a match
requires all three plus a correct or equivalent fix.

## What the recursive arms did — and did not — test

**The falsification criterion in `experiments.md` was not fully exercised.** It
requires compute-matched single-path to match *recursive* Multipath **and** the
full-state-leak ablation to match recursive. Neither recursive nor the leak ablation
ran, for a reason worth recording:

`state_0` on `hoglah-segv` came back with `distinct_solutions: 1` across five
independent paths and zero material disagreement on the cause. That is
`DEGENERATE_POPULATION`, and the method's own rule
(`references/failure-modes.md`) says not to spawn G1 — later generations cannot
decorrelate what G0 did not. **The method declined to run its own recursive stage,
correctly**, and stopped at 5 invocations instead of 15.

That is a real point in its favour, and an unexpected one: the cheapest honest
outcome was reached by a diagnostic that only exists because of the review in
issues #7–#23. It also means the leak ablation — the sharpest test in the design —
remains untested, because a task this easy cannot exercise it.

## The one signal that was not a tie

Accuracy was 7/7. Calibration was not.

The two arms that spent the *most* compute on a single trajectory produced the
confident errors. `single-path-compute-matched` — explicitly told to enumerate ≥4
candidates and self-critique twice — asserted the race was "provably guaranteed" on
an argument it never established, and shipped no uncertainty section at all. Plain
`single-path` and `multipath-g0` each had zero notable errors and flagged the genuine
residual uncertainty (which of two teardown windows fires).

`multipath-g0` preserved that uncertainty because `forbidden_collapses` obliged it
to. That is the machinery doing what it claims — on n=1, judged by one grader.

This is the honest shape of the result: on this family, the population did not buy
accuracy, and may have bought calibration. One task is not evidence for the second
half of that sentence.

## Scope — what this does not show

- **One domain.** Single-root-cause debugging with full source access and an
  objective oracle. The method's stated targets also include research synthesis,
  architecture, and decision analysis, where no oracle exists. Nothing here speaks to
  those, and the `STABLE_WITH_UNCERTAINTY` success criterion was never exercised.
- **One model.** All paths were the same model at the same settings, so
  `error_correlation_risk: "high"` throughout. The mixed-model condition is untested.
- **Four tasks.** No statistical claim is made or available.
- **A grader that is also a language model,** applying pre-registered elements. It
  found real errors in three answers, so it was not merely rubber-stamping, but it is
  not an independent oracle.
- **Selection.** Tasks were chosen before any condition was run, on a criterion
  (the original engineer guessed wrong) that turned out not to predict difficulty
  here. No task was dropped after seeing results.

## What would actually test this

The bottleneck is task difficulty, not experimental design. A discriminating task
needs a cause that a careful single read does not surface — genuinely distributed
across components, or under-determined by the available evidence. Mining bug-fix
commits did not produce one in four attempts.

Until such tasks exist, the defensible claim is narrow:

> On single-root-cause debugging tasks with an oracle and full source access, one
> tool-using trajectory is sufficient, and Multipath's cost is not repaid in accuracy.
> Its own degenerate-population diagnostic correctly detects this and stops early.

## A gap this run exposed

`conserved_findings[].support` has no value meaning **verified by execution**. Four
paths independently reproduced the segfault and measured it — stronger evidence than
either `source` or `reconstructed` — and the enum cannot express it. It was recorded
as `source` with the distortion noted. Worth a `verified` value, or an explicit
`verification: {artifact, result}` field.

## Reproducing

Raw path files, `state.json`, projected views, and grader verdicts are in the run
tree referenced by each record's `artifact_dir`. The `state_0` for `hoglah-segv`
validates clean under:

```bash
python3 skill/scripts/validate_state.py state.json --source source.md --run-dir gen-0
```

It did not validate on the first attempt: `verified_stable_claims` held paraphrases
rather than exact `conserved_findings` claim strings, and the support↔stability
binding added for issue #18 rejected it. That check earned its place on live data.
